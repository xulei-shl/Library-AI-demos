# 05 - 检索核心

> 覆盖：向量检索、带过滤的混合向量检索、BM25 检索
> 路径：`vector_searcher.py`、`hybrid_vector_searcher.py`、`bm25_searcher.py`
> 更深入的算法说明见 [`../检索架构说明.md`](../检索架构说明.md) 第二、三节

---

## 1. 三者关系

```
vector_searcher.VectorSearcher          基础语义检索（ChromaDB）
        ▲ 被装饰
hybrid_vector_searcher.HybridVectorSearcher  在向量检索上叠加 filter_conditions
bm25_searcher.BM25Searcher             独立的字面检索（rank_bm25 + jieba）
```

检索编排时：向量路用 `HybridVectorSearcher`，BM25 路用 `BM25Searcher`，两者结果交给 `RRFFusion`（见 06）。

## 2. vector_searcher.py — `VectorSearcher`

基于 ChromaDB 的语义检索 + 索引构建。内部聚合三个 helper：
- `_EmbeddingClient`：OpenAI 兼容 embedding API（httpx，带重试、环境变量解析）。
- `_VectorStore`：ChromaDB `PersistentClient` 封装（`add / add_batch / search(where=...)`）。
- `_DatabaseReader`：读 `books` 表、回写 `embedding_status`。

### 关键方法
- `search(query_text, top_k=50, min_confidence=0.65, query_expansion=True, dynamic_threshold=True) -> List[Dict]`：
  1. `_preprocess_query` 清洗。
  2. `_expand_query` 生成多路查询变体（去连接词 / 提核心 / 提目标）。
  3. 多路融合：每路独立检索，**每本书保留最高相似度**。
  4. **动态阈值**：`actual_threshold = max(avg_top5 * 0.85, min_confidence * 0.7)`，避免高质量查询过松、低质量查询过严。
  5. 用 `_DatabaseReader` 富化（书名/作者/标签），返回按 `vector_score` 排序的结果。
- `build_index(books, batch_size=32)`：建 ChromaDB 索引。

### 索引文本加权（`_build_context_text`）
```
高权重(1.5x): tags_json.reasoning(重复2次) + 各维度标签
中权重(1.0x): douban_summary(截断500) + 书名+副标题+作者
低权重(0.5x): douban_author_intro(截断200) + douban_catalog(截断300)
```
权重通过"重复拼接"实现，使向量更关注标签语义。

## 3. hybrid_vector_searcher.py — `HybridVectorSearcher`

**装饰器模式**包装 `VectorSearcher`，按 `filter_conditions` 过滤。

- `search(query_text, filter_conditions, top_k=50, min_confidence=0.65, excluded_ids) -> List[Dict]`
- `_search_without_should(...)`：
  - `MUST` → ChromaDB `where` **Pre-filter**（注意：ChromaDB `where` 仅支持 AND，单值）。
  - `MUST_NOT` → 检索后 **Post-filter**（对逗号分隔的 metadata 做集合差）。
- `_search_with_should(...)`：
  - 把每个 SHOULD 值**展开为多路独立查询**，合并结果时每本书取最高相似度。
- 出错时降级：放宽阈值退回基础检索器。
- 结果标记 `source: "vector"`。

## 4. bm25_searcher.py — `BM25Searcher`

字面关键词召回，独立于向量。

- `BM25Searcher(db_path, table="literary_tags", k1=1.5, b=0.75, field_weights)`。
- **懒加载**：首次 `search` 才 `_load_index()`（读 `llm_status='success'` 的行，构建语料 + 缓存书目信息）。
- `search(keywords, top_k=50, excluded_ids) -> List[Dict]`：jieba 分词 → BM25 打分 → 返回带 `bm25_score` 的结果（`source: "bm25"`）。
- `search_with_randomness(keywords, top_k, excluded_ids, randomness=0.15, score_threshold)`：
  - 自动推断阈值：`scores[top_k*3] * 0.5`。
  - `main_count = top_k * (1 - randomness)` 高分结果 + `random_count = top_k * randomness` 从低分候选池随机采样。
  - 增加不同主题间书单的多样性；随机部分标 `source: "bm25_random"`。
- `_build_doc_text(book)`：按 `field_weights` 重复字段（title 2.0 / author 1.0 / summary 1.5）。

## 5. 交接要点
- 改 embedding 模型 / 向量库路径 → 改 `config/literature_fm_vector.yaml` 的 `embedding` / `vector_db`。
- `ChromaDB where` 只支持 AND 单值，这是 `MUST` 只能单值的根因；多值 MUST 需改造或改为 SHOULD 展开。
- BM25 的"随机性"是故意设计（避免书单趋同），调参见 `检索架构说明.md` 4.2。
- 索引文本权重直接决定检索偏向，调权重等同于调推荐口味，需谨慎。
