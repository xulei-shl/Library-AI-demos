# 06 - 融合与重排序

> 覆盖：RRF 融合、CrossEncoder 重排序
> 路径：`rrf_fusion.py`、`cross_encoder_reranker.py`

---

## 1. 为什么用 RRF

向量检索相似度（0–1）与 BM25 分数（0–10+）量纲不同，直接加权平均需要先归一化。RRF（Reciprocal Rank Fusion）**只看排名不看分数**：

```
rrf_score(book) = Σ 1 / (k + rank_i)
```

- `k`：平滑常数，默认 60。
- 某书在某路未出现则贡献为 0。
- 对异常值鲁棒、实现简单（O(n)）。

---

## 2. rrf_fusion.py — `RRFFusion`

- `RRFFusion(k=60)`。
- `merge(results_a, results_b, rank_key_a="vector_score", rank_key_b="bm25_score") -> List[Dict]`：
  - 两路融合，输出按 `rrf_score` 降序。
  - 附加字段：`rrf_score / sources / vector_rank / bm25_rank`。
- `merge_multi(results_list, rank_keys) -> List[Dict]`：N 路融合，记录每路 `ranks`。
- `set_k / get_k`。

**错误处理**：异常时降级返回第一路结果，保证流程不中断。

---

## 3. cross_encoder_reranker.py — `CrossEncoderReranker`

- `CrossEncoderReranker(config)`：内部用 OpenAI 兼容客户端调用重排序模型（默认 `BAAI/bge-reranker-v2-m3`）。
- `rerank(query, results, top_k=30, batch_size=32) -> List[Dict]`：
  1. `_build_doc_text(result)`（书名×2 + reasoning×2 + 摘要，截断 500 字）。
  2. 分批 `_call_reranker_api`（结构化 JSON 输出）。失败则回退为原始顺序（所有分置 0.5）。
  3. 给每本加 `rerank_score` 并重排。
- `is_initialized() / unload()`：资源控制。

**状态**：默认 `reranker.enabled=false`（见 `检索架构说明.md` 4.x）。开启会显著增加延迟与成本，但精排质量更高。

---

## 4. 交接要点
- 融合是"按排名"，所以两路召回数量不一致也没关系（向量受 `min_confidence` 过滤，BM25 只排零分）。
- 新增检索器（如知识图谱路）只需：实现 `search` 返回带 `xxx_score` 的结果 → 在编排处 `rrf_fusion.merge_multi([...], rank_keys=[...])`。
- 重排序器走的是"chat-completions 结构化输出"而非真正的本地 cross-encoder 库——若未来切换本地模型，需改 `_call_reranker_api`。
