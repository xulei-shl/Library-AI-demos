# 04 - 查询意图转换

> 路径：`src/core/literature_fm/query_translator.py`
> 对应 Phase：Phase 2.6（查询意图转换）

---

## 1. 职责

`QueryTranslator` 把"文学策划主题"（自然语言）翻译成下游检索组件能消费的结构化条件：

```json
{
  "filter_conditions": [
    {"field": "spatial_atmosphere", "values": ["荒野自然"], "operator": "SHOULD"},
    {"field": "reading_load",       "values": ["酣畅易读"], "operator": "MUST"}
  ],
  "search_keywords": ["荒野", "星空", "海洋"],
  "synthetic_query": "这本书非常适合那些被信息过载压垮的读者……",
  "original_theme":  { "theme_name": "...", "slogan": "...", "description": "...", "target_vibe": "..." }
}
```

这是连接"主题生成"与"混合检索"的桥梁。

---

## 2. 关键常量（数据契约）
- `VALID_FIELDS`：5 维标签字段
  `reading_context / reading_load / text_texture / spatial_atmosphere / emotional_tone`
- `VALID_OPERATORS`：`SHOULD / MUST / MUST_NOT`
- 字段候选值来自 `literary_tags_vocabulary.yaml`（注入 prompt）。

---

## 3. QueryTranslator

- `QueryTranslator(config, vocabulary_file=None)`。
- `translate_theme(theme_name, slogan, description, target_vibe) -> Dict`：
  - 成功返回上述结构；失败返回带 `is_fallback=True` 与 `error` 的兜底结果。
- `translate_from_excel(excel_path, status_column="候选状态", status_value="通过")`：仅转换"候选状态 == 通过"的行。
- `translate_from_json(json_path)`：批量转换。
- `_validate_result(result)`：**严格校验**——关键词 ≥ 2 个、synthetic_query ≥ 20 字符等；不合法则触发兜底。
- `_get_fallback_result(...)`：LLM 失败时的兜底——用正则从中文描述里抽取关键词，保证流程不中断。
- `_save_results(...)`：写 JSON + 展平后的 Excel。

**输入**：主题 dict（或 Excel/JSON 文件）。
**输出**：`translated_queries`（列表），作为 `generate_theme_shelf` / API 的输入。

---

## 4. 过滤条件语义（下游消费方约定）
| operator | 含义 | 检索实现 |
|----------|------|----------|
| `MUST` | 必须满足 | 向量 Pre-filter（ChromaDB `where`） |
| `MUST_NOT` | 必须排除 | 检索后 Post-filter |
| `SHOULD` | 优选匹配 | 多路检索合并（见 05-检索核心） |

---

## 5. 交接要点
- 转换器是"软失败"设计：LLM 不可用时也要产出可继续检索的兜底结果，**不要去掉兜底分支**。
- 改 5 维标签字段名 / 候选值，必须同步 `literary_tags_vocabulary.yaml` 与 `VALID_FIELDS`。
- `synthetic_query` 是喂给向量检索的文本，`search_keywords` 是喂给 BM25 的，两者用途不同，勿混淆。
