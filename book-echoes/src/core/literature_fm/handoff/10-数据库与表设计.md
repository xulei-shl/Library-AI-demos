# 10 - 数据库与表设计

> 覆盖：文学书目元数据来源（`books`）、文学打标表（`literary_tags`）、推荐历史表（`literature_recommendation_history`）三张表的设计、约束、状态机与访问入口
> 关键文件：`src/core/literature_fm/db_init.py`、`src/core/literature_fm/tag_manager.py`、`src/core/literature_fm/db_vectorizer.py`、`src/core/douban/database/database_manager.py`

---

## 1. 数据库位置与归属

| 项目 | 说明 |
|------|------|
| 物理文件 | `runtime/database/books_history.db`（SQLite） |
| 建表入口 | `src/core/literature_fm/db_init.py`（`init_literary_tags_table`、`init_recommendation_history_table`） |
| 元数据来源表 | `books` 由豆瓣模块 `src/core/douban/database/database_manager.py` 的 `_create_books_table` 创建，**非文学模块自建**，文学模块仅读取、不写 |
| 访问约定 | 文学模块内通过 `sqlite3.connect(db_path)` 直连；`db_path` 默认 `runtime/database/books_history.db` |

> 文学模块涉及三张表：`books`（书目元数据，外部拥有）、`literary_tags`（打标结果，本模块核心）、`literature_recommendation_history`（推荐历史，去重依赖）。

## 2. `books` 表（书目元数据，只读来源）

由豆瓣模块创建。文学链路主要在**打标**与**向量化**阶段读取其字段，作为 LLM 打标的上下文输入。与文学链路强相关的字段：

| 列 | 类型 | 说明 | 文学链路用途 |
|----|------|------|--------------|
| `id` | INTEGER PK | 书目主键 | **关联键**：`literary_tags.book_id` 指向它 |
| `barcode` | TEXT UNIQUE | 条码 | 业务主键（非文学关联键） |
| `call_no` | TEXT | 索书号 | 打标/导出携带；`literary_tags` 冗余存一份 |
| `book_title` | TEXT | 书名 | 打标/检索展示 |
| `douban_title` | TEXT | 豆瓣书名 | LLM 打标 prompt 优先取 `douban_title` |
| `douban_author` | TEXT | 豆瓣作者 | 打标/检索 |
| `douban_subtitle` | TEXT | 副标题 | 向量化拼文本 |
| `douban_summary` | TEXT | 内容简介 | 打标 prompt、向量化中权重字段 |
| `douban_author_intro` | TEXT | 作者简介 | 向量化低权重字段 |
| `douban_rating` | REAL | 豆瓣评分 | 编排器过滤 `min_douban_rating` |
| `douban_pub_year` | INTEGER | 出版年 | 打标/导出 |

> 完整 `books` 表还包括 `douban_url / douban_translator / douban_publisher / douban_series / douban_pages / douban_binding / douban_rating_count / douban_catalog / douban_cover_image` 等，详见 `database_manager.py:98`。文学模块只读取其中一部分，不修改。

**读取示例**（打标、失败记录重取、编排器过滤均如此）：
```python
SELECT b.id, b.book_title, b.douban_author, b.call_no,
       b.douban_summary, b.douban_rating, b.douban_pub_year
FROM books b
INNER JOIN literary_tags lt ON b.id = lt.book_id
```

## 3. `literary_tags` 表（打标结果，本模块核心）

### 3.1 建表与自升级

`db_init.init_literary_tags_table`（`db_init.py:14`）先建基础表，再用 `pragma_table_info` 自检后 `ALTER` **补齐三列向量化字段**（幂等，可重复调用）：

```sql
CREATE TABLE IF NOT EXISTS literary_tags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    book_id INTEGER NOT NULL,
    call_no TEXT,
    title TEXT,
    tags_json TEXT,                       -- 5 维标签 JSON
    llm_model TEXT,
    llm_provider TEXT,
    llm_status TEXT DEFAULT 'pending',
    retry_count INTEGER DEFAULT 0,
    error_message TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(book_id)
);
-- 自升级追加（若不存在）：
ALTER TABLE literary_tags ADD COLUMN embedding_status TEXT DEFAULT 'pending';
ALTER TABLE literary_tags ADD COLUMN embedding_id TEXT;
ALTER TABLE literary_tags ADD COLUMN embedding_date TEXT;
```

### 3.2 完整列清单（含 ALTER 追加）

| 列 | 类型 | 默认值 | 说明 |
|----|------|--------|------|
| `id` | INTEGER PK | 自增 | 行主键 |
| `book_id` | INTEGER | — | **唯一约束**，指向 `books.id`；`INSERT OR REPLACE` 依赖它 |
| `call_no` | TEXT | NULL | 索书号（冗余自 `books`） |
| `title` | TEXT | NULL | 书名（冗余自 `books`） |
| `tags_json` | TEXT | NULL | **核心**：5 维标签 JSON，见 §4 |
| `llm_model` | TEXT | NULL | 打标所用模型 |
| `llm_provider` | TEXT | NULL | 打标所用 provider |
| `llm_status` | TEXT | `'pending'` | 打标状态机（见 §5） |
| `retry_count` | INTEGER | `0` | 兜底重试次数 |
| `error_message` | TEXT | NULL | 失败原因 |
| `created_at` | TIMESTAMP | 当前 | 创建时间 |
| `updated_at` | TIMESTAMP | 当前 | 更新时间 |
| `embedding_status` | TEXT | `'pending'` | 向量化状态机（见 §6） |
| `embedding_id` | TEXT | NULL | ChromaDB 中的向量 id |
| `embedding_date` | TEXT | NULL | 向量化完成时间 |

### 3.3 索引

`db_init` 与 `import_literary_tags.show_table_structure` 共同约定的索引：
- `idx_literary_tags_book_id` ON `(book_id)`
- `Idx_literary_tags_status` ON `(llm_status)`
- `idx_literary_tags_call_no` ON `(call_no)`

### 3.4 访问入口（CRUD）

统一经 `src/core/literature_fm/tag_manager.py` 的 `TagManager`（不要在别处直写 SQL）：

| 方法 | 作用 |
|------|------|
| `save_tags(...)` | `INSERT OR REPLACE`（按 `book_id` 幂等落库） |
| `update_status(book_id, llm_status, error_message, increment_retry=False)` | 更新状态/失败原因，可选 `retry_count+1` |
| `get_tagged_book_ids(status='success')` | 取已成功 `book_id`，编排器用于排除已打标 |
| `get_failed_records(max_retry_count=3)` | JOIN `books` 取待重试行 |
| `export_to_dataframe()` | 仅成功行，供导出 Excel |

导入工具 `import_literary_tags.import_data(rows, replace=False)` 支持从 xlsx/csv 批量写入，`replace=True` 时按 `book_id` `ON CONFLICT ... DO UPDATE`（`import_literary_tags.py:80`）。

## 4. `tags_json` 数据契约（5 维标签）

`tags_json` 是贯穿全链路的核心数据契约，由 `config/literary_tags_vocabulary.yaml` 提供候选值并注入 LLM prompt。结构：

```json
{
  "reading_context":      ["暮色四合时", "深夜独处"],
  "reading_load":         ["酣畅易读"],
  "text_texture":         ["诗意流动"],
  "spatial_atmosphere":   ["都市孤独"],
  "emotional_tone":       ["温暖治愈"],
  "confidence_scores":    { "reading_context": 0.9, "reading_load": 0.8, "...": 0.7 },
  "reasoning": "……"
}
```

- 维度键：`reading_context / reading_load / text_texture / spatial_atmosphere / emotional_tone`。
- `_validate_tags`（`llm_tagger.py`）校验 5 维齐全、置信度 ≥ 阈值（默认 0.65），否则降级打日志。
- 任何与标签相关的修改都要同步核对 `literary_tags_vocabulary.yaml`。

## 5. `llm_status` 状态机（打标）

| 状态 | 含义 | 写入方 |
|------|------|--------|
| `pending` | 待打标（默认值） | 建表默认 |
| `success` | 打标成功，`tags_json` 有效 | `TagManager.save_tags` |
| `failed` | 打标失败，`error_message` 有原因 | `LLMTagger._tag_single_book` 异常分支 |

重试流：`get_failed_records(max_retry_count=3)` 取 `status='failed' AND retry_count < 3` 的行 → `LLMTagger.fallback_retry` 并行重试 → `update_status(..., increment_retry=True)` 累加 `retry_count`。

---

## 6. `embedding_status` 状态机（向量化）

由 `db_vectorizer.py` 维护，三态（`db_vectorizer.update_embedding_status`，`db_init` 默认 `'pending'`）：

| 状态 | 含义 | 写入方 |
|------|------|--------|
| `pending` | 未向量化 | 建表默认 |
| `completed` | 已写入 ChromaDB，`embedding_id` 已回填 | `db_vectorizer.vectorize_database` 成功 |
| `failed` | 向量化失败 | `db_vectorizer.vectorize_database` 异常 |

- `get_books_to_vectorize`：取 `llm_status='success' AND (embedding_status IS NULL OR embedding_status != 'completed')`，**支持断点续跑**。
- `clear_vector_collection`：破坏性重置 `embedding_status=NULL` 并清 ChromaDB，需入参 `YES_I_CONFIRM`（`db_vectorizer.py:261`）。
- 排查"检索不到某书"：先确认 `embedding_status='completed'`。

## 7. `literature_recommendation_history` 表（推荐历史，去重依赖）

`db_init.init_recommendation_history_table`（`db_init.py:105`）创建，记录每次推荐产出的书目集合，供 `theme_deduplicator` 排除历史已推荐项。

```sql
CREATE TABLE IF NOT EXISTS literature_recommendation_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_input TEXT NOT NULL,           -- 用户/主题输入
    llm_conditions TEXT NOT NULL,       -- 翻译后的检索条件
    final_theme TEXT,                   -- 最终主题
    book_ids TEXT NOT NULL,             -- 推荐书目 book_id 列表（JSON/文本）
    passed_book_ids TEXT,               -- 二次筛选后保留的 book_id
    use_vector INTEGER DEFAULT 0,       -- 是否启用向量检索
    vector_weight REAL DEFAULT 0.5,     -- 向量权重（RRF）
    randomness REAL DEFAULT 0.2,        -- 随机性参数
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

索引：`idx_history_input` ON `(user_input)`、`idx_history_conditions` ON `(llm_conditions)`。

> 调试"为什么某本书没出来"：先查 `literature_recommendation_history` 是否被历史去重排掉。

## 8. 表间关系与数据流

```
books (id PK) ──1:1──▶ literary_tags (book_id UNIQUE)
   │                       │
   │ 打标读取 (douban_*)   │ tags_json → 向量化 → ChromaDB
   │                       │ embedding_status/embedding_id 回填
   ▼                       ▼
literature_recommendation_history (book_ids 引用 books.id，去重依赖)
```

- `books` ↔ `literary_tags`：通过 `literary_tags.book_id = books.id`，`UNIQUE(book_id)` 保证每书一行。
- `literary_tags` → ChromaDB：`embedding_id` 建立逻辑关联（非表外键）。
- `literature_recommendation_history.book_ids` 为逻辑引用，记录 `books.id` 集合。

---

## 9. 交接要点

1. **`books` 是外部表**，文学模块只读不写；新增书目元数据读取需求时改 `books` 表要在豆瓣模块 `database_manager.py` 同步。
2. **落库统一走 `TagManager.save_tags`**（或 `import_literary_tags`），勿在别处直写 `literary_tags` SQL。
3. **三态状态机**：`llm_status`（打标）与 `embedding_status`（向量化）是两个独立维度，互不影响；"打标成功 ≠ 已向量化"，需单独执行 `cli.py vectorize`。
4. **自升级模式**：新增列照 `db_init.init_literary_tags_table` 的 `pragma_table_info` + `ALTER` 模式做，保证老库兼容、可重复调用。
5. **去重依赖历史表**：改推荐逻辑先想清楚 `literature_recommendation_history` 的写入与读取。
6. **标签契约同步**：改 `tags_json` 结构或 5 维候选值，必须同步 `config/literary_tags_vocabulary.yaml`。
