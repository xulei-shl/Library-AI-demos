# 02 - 打标流水线

> 覆盖：LLM 打标、标签表 CRUD、建表升级、批量向量化、CSV/XLSX 导入
> 路径：`llm_tagger.py`、`tag_manager.py`、`db_init.py`、`db_vectorizer.py`、`import_literary_tags.py`

---

## 1. 数据契约：5 维标签

每本书的标签 JSON（`tags_json`）结构：
```json
{
  "reading_context":  ["暮色四合时", "深夜独处"],
  "reading_load":     ["酣畅易读"],
  "text_texture":     ["诗意流动"],
  "spatial_atmosphere":["都市孤独"],
  "emotional_tone":   ["温暖治愈"],
  "confidence_scores": { "reading_context": 0.9, "...": 0.8 },
  "reasoning": "……"
}
```
候选值来自 `config/literary_tags_vocabulary.yaml`，会被注入 LLM prompt 以提供上下文。

---

## 2. llm_tagger.py — `LLMTagger`

职责：批量调用 LLM 给书目打标并落库。

- `LLMTagger(config)`：内部持有 `UnifiedLLMClient`、`TagManager`、已加载的词表。
- `tag_books(books) -> {success, failed}`：按 `batch_size` 分批、每批内用 `ThreadPoolExecutor(max_workers=concurrency)` **并行**调用 `_tag_single_book`，批次间 `time.sleep` 节流。`concurrency=1` 时等价于串行。
- `_tag_single_book(book) -> bool`：拼 prompt → 调 LLM → JSON 解析（`json_repair`）→ `_validate_tags` → `TagManager.save_tags`；失败记录 `error_message`。
- `_validate_tags`：检查 5 维键齐全、置信度不低于阈值（默认 0.65），低置信度写日志。
- `fallback_retry() -> {success, failed}`：对 `get_failed_records` 取回的失败记录，同样用 `ThreadPoolExecutor` **并行**重试（复用 `concurrency` 配置）；失败时自动 `update_status(increment_retry=True)`。

**输入**：书目 dict（`id / book_title / douban_author / call_no / douban_summary / douban_rating / douban_pub_year` 等）。
**输出**：写入 `literary_tags` 表；返回统计。

依赖：`src.utils.llm.client.UnifiedLLMClient`、`tag_manager`、词表 YAML。

---

## 3. tag_manager.py — `TagManager`

职责：`literary_tags` 表的 CRUD 封装。构造时自动 `db_init.init_literary_tags_table`。

- `get_tagged_book_ids(status) -> List[int]`：取已成功打标的 `book_id`（编排器用于排除）。
- `save_tags(book_id, call_no, title, tags_json, llm_model, llm_provider, llm_status='success', error_message=None) -> bool`：`INSERT OR REPLACE`，依赖 `UNIQUE(book_id)`。
- `update_status(book_id, llm_status, error_message, increment_retry=False) -> bool`。
- `get_failed_records(max_retry_count=3) -> List[Dict]`：JOIN `books` 取出待重试行。
- `export_to_dataframe() -> pd.DataFrame`：仅成功行，供导出。

---

## 4. db_init.py — 建表与升级

- `init_literary_tags_table(db_path) -> bool`：建表 + 用 `pragma_table_info` 自检后 `ALTER` 补齐 `embedding_status / embedding_id / embedding_date` 列；建索引（`book_id / llm_status / call_no`）。**幂等**（可重复调用）。
- `init_recommendation_history_table(db_path) -> bool`：推荐历史表 + 索引。

所有写库模块都依赖它在首次运行时确保表存在。

---

## 5. db_vectorizer.py — 批量向量化

职责：把已打标图书嵌入 ChromaDB，并回写 `embedding_status`。

- `get_books_to_vectorize(db_path, batch_size=100)`：取未向量化 / 状态非 `completed` 的图书。
- `vectorize_database(db_path, config_path, batch_size=50, max_books=0) -> Dict`：循环 → `VectorSearcher._build_context_text` 拼文本 → `embedding_client.get_embedding` → `vector_store.add`，返回统计。
- `get_vectorize_status() -> Dict`：返回 `total_tagged / vectorized / pending / failed / progress%`。
- `clear_vector_collection(...) -> bool`：**破坏性**，需入参确认 `YES_I_CONFIRM`，清空后重置状态。
- `main()`：argparse 入口（`--batch-size / --max / --status / --clear / --confirm-clear`）。

**设计**：可断点续跑（跳过 `completed`）；CLI 直接可调用。

---

## 6. import_literary_tags.py — 标签导入工具

职责：从 xlsx/csv 批量导入标签到 `literary_tags`。

- `read_file(path)` → `read_xlsx` / `read_csv` 按扩展名分派。
- `import_data(db_path, rows, replace=False) -> (success, failed)`：`INSERT`，`replace=True` 时 `ON CONFLICT(book_id) DO UPDATE`。
- `show_table_structure()` / `main()`（argparse：`file / --db / --replace / --show-structure`）。

用于从外部（人工整理 / 其他系统）导入标签，绕过 LLM。

---

## 7. 交接要点
- **标签落库统一走 `TagManager.save_tags`**，新增标签来源时勿直写 SQL。
- 向量化是独立步骤（`vectorize_database`），打完标不会自动向量化——上线/重跑后记得执行 `cli.py vectorize`。
- `embedding_status` 三态（未处理 / 处理中 / completed）由 `db_vectorizer` 维护，排查"检索不到某书"先确认它已完成向量化。
- `db_init` 的 `ALTER` 自升级逻辑保证了老库兼容，新增列时照此模式加。
- **并发控制**：`config/literature_fm.yaml` → `llm_tagging.batch_processing.concurrency` 控制每批内并行 LLM 调用数。设为 `1` 等价于纯串行（向后兼容）。调高可加速打标，注意 API 限流。
